# Cyber-Projects
Lab File Permission Overview. Step 1: Creating Groups and Users, I started by creating three distinct user groups in my terminal using the groupadd command: employee, payroll, and admin.   I then added my own primary user account to the system as a custom group (jgait001).   Next, I created three users—sophia, olivia, and emma—using useradd, configured their home directories, and set their passwords.   I assigned sophia to the employee group, olivia to the payroll group, and emma to the admin group. I also added all three users to my jgait001 group using usermod -aG to verify their group memberships.   Step 2: Creating and Securing the Project DirectoryI created a shared directory at /home/cyse_project using sudo mkdir.   I changed the ownership of this directory to my user account (jgait001) using sudo chown.   To secure the folder, I set the permissions to 770 using sudo chmod, meaning that the owner and members of the group have full read, write, and execute permissions, while others have no access.   Step 3: Task A (Working with Standard Group Permissions)I switched to the user sophia (sudo su sophia) and created a file named Sophia_homework inside her home directory containing my name, "Justin Gaither".   I copied this homework file into the shared directory /home/cyse_project/.   When I checked the permissions and ownership, the file was owned by sophia and the employee group. Because the directory inheritance was standard, other users in different groups (like emma from admin) could still read the file based on its default permissions (-rw-r--r--).   Step 4: Task B (Testing the SGID Bit)Back as the root/student user, I enabled the SetGroupID (SGID) bit on the shared directory by running sudo chmod g+s /home/cyse_project.   I switched back to sophia and copied the file again as Sophia_homework2 into the shared folder.   With the SGID bit enabled, any new files created in this directory automatically inherit the group ownership of the parent directory rather than the creator's primary group, ensuring collaborative consistency.   Step 5: Task C (Removing the SGID Bit)Finally, I removed the SGID bit from the shared directory by running sudo chmod g-s /home/cyse_project.   I logged in as sophia one last time to copy Sophia_homework3 into the shared directory.   This reverted the folder behavior back to default, where newly created files take on the user's default primary group instead of forcing inheritance from the shared parent folder.
